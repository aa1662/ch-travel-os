# CH Travel Blog Workflow

這是本專案 2026-10-17 起的流程入口。正式規則留在 repository，不在 skill 複製第二套文風或工具契約。

## 按任務讀取

- 新篇、選圖、母稿與構建：讀取根目錄 [Production Playbook](../../../TRAVEL_BLOG_PRODUCTION_PLAYBOOK.md)。
- 口述、grillme、潤飾與內容 review：另讀 [Editorial Style Guide](../../../EDITORIAL_STYLE_GUIDE.md)。
- 分篇、URL 或網站入口：需要時讀 [Portal Roadmap](../../../TRAVEL_PORTAL_ROADMAP.md)。
- 再讀本篇 plan 的最新決策及相關素材，不全量載入其他旅程與歷史沿革。

找不到專案或 Playbook 時先確認路徑，不憑記憶重建規則。

## 新篇工作方式

1. 從作者集中候選照片的私人資料夾開始看圖，協助作者口述並同步標記想用、不用與待決照片；不先全量製作公開縮圖。
2. 潤飾前主動用必要的 grillme 討論怎麼寫、分篇、語氣與呈現。照片小品不必硬寫深度長篇；已清楚的決策不重問。
3. IG 欄數、圖文配置、點開原圖或調色版及 caption 都逐篇討論，記在既有 plan 的最新摘要；既有案例是參考，不是黃金公式。
4. 母稿與最終選圖確認後，只為入選照片製作公開縮圖及必要尺寸，再完成排版。私人看圖預覽與公開 derivatives 分開；不把資料夾所有檔案視為入選。
5. 沿用既有 source/config、builder、圖片管線與驗收。Gallery 去重依照片版本與作者決策，不抹除刻意保留的 IG 裁切／調色。

## 任務邊界

- 作者擁有記憶、選圖與公開決策。不得從照片發明感受或重要事件；適度比喻、旁白與已核准幽默依 Style Guide 保留。
- 選圖可直接在看圖口述中完成；Editor 是可選工具，draft scaffold 不是開始取材的前提，也不代表已公開。
- 舊 plan 與全域舊入口若描述不同的製作順序，以本專案現行 Playbook 及作者本篇最新確認為準。
- 流程改版不修改任何已完成文章。只有作者指定既有篇修改時才操作該篇；小改稿沿用相稱驗證，不重跑新篇。
- 作者判斷故事、語氣、選圖與閱讀效果；AI 自行完成圖文核對、技術與視覺檢查。核准正文不被 caption／gallery 修正連帶改寫。
- 原圖與 Takeout 不進公開目錄或 Git。只在當次明確授權範圍內 commit、push、deploy 或 publish；部署另讀 [部署指引](../../../CLOUDFLARE_PAGES_DEPLOYMENT.md)。
